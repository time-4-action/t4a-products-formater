# point7-to-shopify — Claude Code Context

## What this is
A Python script that converts a **Point-7 products JSON** export into a **Shopify product import CSV**.

## Files
- `point7-to-shopify.py` — the converter script
- `point-7.json` — source product data (Point-7 internal format)
- `shopify_import.csv` — output (generated by the script)

## Usage
```bash
python point7-to-shopify.py point-7.json shopify_import.csv
```

## Input JSON structure (`point-7.json`)
Top-level keys are product categories. Each value is a list of product entries:
```json
{
  "parts":      [...],
  "components": [...],
  "apparel":    [...],
  "bags":       [...],
  "":           [...],   // unnamed → tagged "Boards & Sails"
  "sails":      [...]
}
```

Each product entry has these fields:
```json
{
  "name":            "Impact Vest Zipped - M",
  "TypeURLA":            "m",
  "description":     "Plain text with \\r\\n newlines and [xyz-ihs snippet=...] shortcodes",
  "image":           "https://point-7.com/.../full.jpg",
  "image medium":    "https://point-7.com/.../full-400x400.jpg",
  "id":              1956,
  "sku":             "23ACIVZM",
  "ean":             "0782706458544",
  "ex sx3 preorder": "84",
  "sx3 single item": "84",
  "eu rrp":          "105,74",
  "eu rrp +vat":     "129",
  "inventory":       "1"
}
```

**Variants**: multiple entries sharing the same `id` → one Shopify product with multiple variants, differentiated by `TypeURLA`.

## Shopify CSV output format
Follows standard Shopify product import format (same as Matrixify-compatible):

| Column | Source |
|--------|--------|
| Handle | slugified product title |
| Title | base product name (TypeURLA suffix stripped for parts/components/apparel/bags) |
| Body (HTML) | description converted to `<p>` / `<br>` HTML |
| Vendor | hardcoded `"Point-7"` |
| Tags | category name (e.g. `"Parts"`, `"Boards & Sails"`) |
| Option1 Name | `"TypeURLA"` for multi-variant, `"Title"` for single |
| Option1 Value | `TypeURLA` field value, or `"Default Title"` for single |
| Variant SKU | `sku` |
| Variant Price | `eu rrp +vat` (comma → dot) |
| Variant Compare At Price | `eu rrp` (only if different from price) |
| Variant Inventory Qty | `inventory` |
| Variant Barcode | `ean` |
| Image Src | `image` (full-res); medium image added as extra image-only row |
| Variant Image | same as Image Src (only set for multi-variant products) |

## Key logic / decisions

### Grouping into variants
Products are grouped by `id`. All entries with the same `id` become variants of one Shopify product.

### Title stripping
For `parts`, `components`, `apparel`, `bags`: the `TypeURLA` is a suffix on the name.  
`"Impact Vest Zipped - M"` + TypeURLA `"m"` → title `"Impact Vest Zipped"`

For `""` (boards) and `"sails"`: the name is already clean — no stripping applied.  
`"SALTpro | The Wave 026"` stays as-is.

### Description conversion
- WP shortcodes `[xyz-ihs snippet="..."]` are stripped
- `\r\n\r\n` (blank lines) → paragraph breaks → `<p>...</p>`
- `\r\n` (single newline) → `<br>`
- Output is a single-line HTML string (no literal newlines, CSV-safe)

### Category → Shopify tag mapping
```python
CATEGORY_TAG = {
    "parts":      "Parts",
    "components": "Components",
    "apparel":    "Apparel",
    "bags":       "Bags",
    "":           "Boards & Sails",
    "sails":      "Sails",
}
```

### Image rows
- Each variant row gets its own `Image Src` and `Variant Image`
- Medium images (`image medium`) are added as extra image-only rows (Handle + Image Src only) if they differ from the full-res URL

## Potential next steps / known issues
- `TypeURLA` values for sails are like `"5-6 - Stitched"` — could be split into Option1=Size, Option2=Construction if Shopify needs two option axes
- Some variants have no SKU (empty string) — these are Qbond variants without a code yet
- `inventory` is always 0 or 1 in current data — no quantity tracking beyond in/out of stock
- Vendor is hardcoded as `"Point-7"` — adjust if importing under a different brand name
