# point7-to-shopify -- Claude Code Context

## What this is
A Python script that converts a **Point-7 products JSON** export into a **Shopify product import CSV** and a **Shopify inventory CSV**, with AI-powered product categorization.

## Files
- `point7-to-shopify.py` -- the converter script
- `products.json` -- source product data (Point-7 internal format)
- `shopify_import.csv` -- output product CSV (generated by the script)
- `shopify_import_inventory.csv` -- output inventory CSV (generated by the script)
- `category_cache.json` -- cached AI categorization results (auto-generated, delete to re-categorize)
- `.env` -- environment variables (`WEBHOOK_API_KEY`, `EXPORT_ID`)
- `CATEGORIZATION_AI.md` -- API documentation for the categorization endpoint

## Usage
```bash
python point7-to-shopify.py products.json [output.csv]
```
Generates both `shopify_import.csv` and `shopify_import_inventory.csv`.

## Environment variables (`.env`)
| Variable | Description |
|----------|-------------|
| `WEBHOOK_API_KEY` | API key for the AI categorization endpoint |
| `EXPORT_ID` | The export ID whose category set to use for categorization |

## Input JSON structure (`products.json`)
Top-level keys are product categories. Each value is a list of product entries:
```json
{
  "parts":      [...],
  "components": [...],
  "apparel":    [...],
  "bags":       [...],
  "":           [...],   // unnamed -- tagged "Boards & Sails" (fallback)
  "sails":      [...]
}
```

Each product entry has these fields:
```json
{
  "name":            "Impact Vest Zipped - M",
  "type":            "m",
  "description":     "Plain text with \\r\\n newlines and [xyz-ihs snippet=...] shortcodes",
  "image":           "https://point-7.com/.../full.jpg",
  "image medium":    "https://point-7.com/.../full-400x400.jpg",
  "id":              1956,
  "sku":             "23ACIVZM",
  "ean":             "0782706458544",
  "ex sx3 preorder": "84",
  "sx3 single item": "84",
  "eu rrp":          "105,74",
  "eu rrp +vat":     "129",
  "inventory":       "1"
}
```

**Variants**: multiple entries sharing the same `id` = one Shopify product with multiple variants, differentiated by `type`.

## AI Categorization

Products are categorized using the Time-4-Action AI categorization API (Gemini 2.5 Flash).

- **API endpoint**: `POST https://api.time-4-action.com/api/export/webhooks/categorize`
- **Batch size**: 30 products per API request (to avoid timeouts)
- **Cache**: Results are cached in `category_cache.json`. Delete this file to force re-categorization.
- **Fallback**: If API key or export ID is missing, falls back to hardcoded category tags.

### Tag exploding
Category paths like `Katalog / Windsurf / Boards` are exploded into multiple Shopify tags at every level:
```
Katalog, Katalog / Windsurf, Katalog / Windsurf / Boards
```

## SKU Prefix

All SKUs are prefixed with `P7-`. Existing SKUs like `VARIOTOPPIN` become `P7-VARIOTOPPIN`.

Products missing a SKU get a deterministic one generated via SHA-256 hash:
- Input: `{product_id}:{type}` (or `{product_id}:{variant_index}` if type is empty)
- Format: `P7-XXXXXXXX` (8-char uppercase hex hash)
- Same input always produces the same SKU across runs

## Shopify CSV output format
Follows standard Shopify product import format:

| Column | Source |
|--------|--------|
| Handle | slugified product title |
| Title | base product name (type suffix stripped for parts/components/apparel/bags) |
| Body (HTML) | description converted to `<p>` / `<br>` HTML |
| Vendor | `"POINT-7"` |
| Tags | AI-categorized (exploded hierarchy), or fallback category tag |
| Option1 Name | `"Title"` |
| Option1 Value | `type` field value, or `"Default Title"` for single-variant |
| Variant SKU | `P7-` + `sku` from JSON, or auto-generated `P7-XXXXXXXX` |
| Variant Price | `eu rrp +vat` (comma to dot) |
| Variant Compare At Price | `eu rrp` (only if different from price) |
| Variant Inventory Qty | `inventory` |
| Variant Barcode | `ean` |
| Image Src | `image` (full-res); medium image added as extra image-only row |
| Variant Image | same as Image Src (only set for multi-variant products) |

## Inventory CSV output format
Matches Shopify inventory import format (like `benelux_boards_inventory.csv`):

| Column | Description |
|--------|-------------|
| Handle | product handle |
| Title | product title (first variant row only) |
| Option1-3 Name/Value | variant options |
| SKU | variant SKU |
| HS Code | empty |
| COO | empty |
| POINT-7 | inventory quantity at the POINT-7 location |

## Key logic / decisions

### Grouping into variants
Products are grouped by `id`. All entries with the same `id` become variants of one Shopify product.

### Title stripping
For `parts`, `components`, `apparel`, `bags`: the `type` is a suffix on the name.
`"Impact Vest Zipped - M"` + type `"m"` = title `"Impact Vest Zipped"`

For `""` (boards) and `"sails"`: the name is already clean -- no stripping applied.

### Description conversion
- WP shortcodes `[xyz-ihs snippet="..."]` are stripped
- `\r\n\r\n` (blank lines) = paragraph breaks = `<p>...</p>`
- `\r\n` (single newline) = `<br>`
- Output is a single-line HTML string (no literal newlines, CSV-safe)

### Image rows
- Each variant row gets its own `Image Src` and `Variant Image`
- Medium images (`image medium`) are added as extra image-only rows (Handle + Image Src only) if they differ from the full-res URL
